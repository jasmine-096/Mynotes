当两个进程同时向一个文件里写入数据，那这个文件该怎么办？

这就是并发要处理的问题

## 线程

单个运行的进程又被抽象为了线程，单线程是只有一个程序计数器（用来存放执行的指令），多线程是有多个程序计数器，多线程类似与多进程，不同的是，多线程共享同一地址空间，而且进程间的上下文切换不需要更换地址空间（同一进程的多线程之间），也正因如此，多线程的地址空间会有多个栈

线程的运行顺序同样是取决于系统调度的，但这个调度是不可控制的：

在运行`count++`这段代码时，会经过三个步骤：1.从对应的内存取出数值，放入`eax`寄存器中 2.把`eax`中的数加1 3.把`eax`中的数放回内存中

如果有两个线程同时运行这段代码，此时，两线程将`eax`中的数加1并放回去时，两个数会相互覆盖，原本希望是加2，但最终是加1

像这种结果取决于代码执行顺序的情况就被称为**竞态条件**，而这段导致多个线程间处于竞争的代码称为**临界区**，它是访问共享变量的代码段

如果我们能使的在运行临界区时线程处于**互斥**状态就能解决问题

## 锁

在并发编程中，原子式的执行一些命令是让人愉悦的，我们要去解决这些并发问题，而锁就则是此解决问题的一大良策

```C
Pthread_mutex_lock(&lock);
balance = balance +1;
Pthread_mutex_unlock(&lock);
```

就像这样，balance变量就会被保护起来，在完成加1操作后又被解锁

### 如何实现

在实现锁之前，我们先要判断，什么样的锁是好的，是我们需要的；

- 首先，就是能够实现互斥，这是实现锁的最基础的目标
- 其次，在实现互斥的基础上，要保证公平，是否会有进程因为一直占有着锁而导致其他进程饿死呢？
- 最后，性能，锁的设立与释放是否会导致性能开销增大？增大多少？

现在我们来看看如何实现锁：

首先就是上面展示的一段代码，这是最简单的锁的实现——在进入临界区之前关闭中断，保证临界区的代码不会中断，然后解锁——恢复中断指令，这种实现简单明了，但是缺点很多：

- 不能保证公平，关闭中断是一种特权操作，如果让一个线程去执行这种操作，很可能会造成滥用，一直不解锁或一直调用lock()导致系统无法获得控制权（见虚拟化，系统利用中断来重新获得控制权）
- 不支持多处理器，本核上的时钟中断可以让一个线程独享临界区，但是管不住其他核心
- 中断丢失，像磁盘I/O操作是异步的，系统靠中断信号来判断磁盘I/O是否结束，如果中断丢失，系统就会认为磁盘I/O一直在进行，则后面的磁盘I/O一直就无法执行
- 性能低下，执行关闭和打开中断指令的效率很低

如此多的缺点让我们不得不考虑其他的设计思路

#### 测试并设置指令(test-and-set instruction)（原子交换）

测试并设置指令：
```C
int TestAndSet(int *old_ptr,int new){
	int old = *old_ptr;
	*old_ptr = new;
	return old;
}
```


通过这一指令可以设置一个简单的自旋锁：

```C
typedef struct lock_t{
	int flag;
}lock_t;

void init(lock_t *lock){
	lock->flag=0;
}

void lock(lock_t *lock){
	while(TestAndSet(&lock->flag,1) == 1)//在flag为1时一直自旋，直到有线程解锁
		；//spin-wait
}

void unlock(lock_t *lock){
	lock->flag = 0;
}
```

这里一定是需要硬件的支持的——实现测试与设置指令，因为，读旧值与写新值如果不是原子指令，那么两个线程会同时读到旧值0,然后同时以为自己得到了锁，然后一起访问临界区，这违背了我们的初衷！

自旋锁成功实现了在多核cpu下的互斥，但是没有保证公平性，在多核cpu下性能不错

#### 比较并交换(compare-and-swap)

```C
int CompareAndSwap(int *ptr,int expected,int new){
	int actual = *ptr;
	if(actual == expected)
		*ptr = new;
	return actual;
}
```

此指令的基本思想是比较原有值与期待值，如果原有值等于期待值则表示最近没有别的进程修改它，并将原有值更新为新值，如果不相等，则什么也不做

它比TAS更强大，体现在它会判断值有没有被修改，再考虑写入新值，而TAS是无论原来的值怎么样都写入

#### 链接的加载与条件式存储指令(load-linked And store-conditional)

```C
int LoadLinked(int *ptr){
	return *ptr;//标记这块地址
}

int StoreConditional(int *ptr,int value){
	if(no ones updated *ptr since the LoadLinked to this address){
		*ptr = value;
		return 1;//无人修改
	}else{
		return 0;//被修改过！
	}
}
```

使用LL/SC实现锁能降低复杂性：

```C
void lock(lock_t *lock){
	while(1){
		while(LoadLinked(&lock->flag)==1)
			;//自旋等待直到等于0
		if(StroeConditional(&lock->flag,1)==1)
			return;//成功	
	}
}

void unlock(lock_t *lock){
	lock->flag = 0;
}
```

#### 获取并增加(fetch-and-add)

原子性的返回旧值，并让旧值加1：

```C
int FetchAndAdd(int *ptr){
	int old = *ptr;
	*ptr = old+1;
	return old;
}
```

用此指令实现的ticket锁:
```C
typedef struct lock_t{
	int ticket;
	int turn;
}lock_t;

void lock_init(lock_t *lock){
	lock->ticket = 0;
	lock->turn = 0;
}

void lock(lock_t *lock){
	int myturn = FetchAndAdd(&lock->ticket);
	while(lock->turn != myturn)
		;//自旋
}

void unlock(lock_t *lock){
	FetchAndAdd(&lock->turn);
}
```

此方法能确保所有的线程都能抢到锁，在myturn获得ticket时，如果别的线程没解锁，那tuen就不等于myturn,直到解锁
