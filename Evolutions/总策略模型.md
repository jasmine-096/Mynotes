# PML4 0：核心架构

## PDP 0.0 — 建造者哲学

| | 消费者 | 建造者 |
|---|---|---|
| **与信息的关系** | 接收、收藏、划线 | 转译、重组、输出 |
| **学习的终点** | "我懂了" | "我能做出来" |
| **笔记是什么** | 外部记忆 dump | 压缩后的可执行产物 |
| **验证方式** | 感觉 | 关书 → 独立产出 |

**建造者的唯一标准**：关上所有参考资料之后，你能产出什么？

## PDP 0.1 — CPU 流水线

每一天是一条指令流水线。任一阶段断裂，整条指令作废。

```
[FETCH] → [DECODE] → [EXECUTE] → [WRITEBACK]
   ↑                                    ↓
   └──────── 间隔重复 (cache flush) ────┘
```

| 阶段 | 定义 | 你的常见失败模式 |
|---|---|---|
| **FETCH** | 获取信息 | 贪多并行（指令缓存污染） |
| **DECODE** | 理解/转译 | 用「在看视频/划线」冒充「理解了」 |
| **EXECUTE** | 做题/输出/建造 | OSTEP 读完不做比喻；英语读完不输出 |
| **WRITEBACK** | 写入长期记忆 | 笔记是 dump 不是压缩产物，三天后检索率→0 |

**瓶颈诊断**：EXECUTE 阶段结构性空转。

### Hazards

**H1 · 上下文切换（最大亏损源）**

每次任务切换→evict working set→load 新上下文→**15-25 分钟恢复深度**。手机打断约每小时 2 次，恢复 5 分钟/次。每天数学 block 损失约 27.5 分钟。

**H2 · 分支预测失败**

凭「感觉」判断难度 → 预测错误 → 翻车。该用**每章关书抽 5 题**来预估，不是靠感觉。

**H3 · 缓存击穿**

考前突击 = 一次性 load 整本教材进 L1 → 直接溢出。间隔重复 = 定时 flush 到持久存储 → 选择性 reload。

# PML4 1：内存系统

## PDP 1.0 — 间隔重复 (Ebbinghaus)

### 遗忘衰减模型

遗忘是指数衰减，不是线性：

```
R(t) = e^(-t/S)
```

| 符号 | 含义 |
|------|------|
| R(t) | t 天后保留的记忆比例 |
| S | 记忆稳定性，取决于编码深度（复现 < 独立 < 总练） |
| t | 距上次检索的天数 |

**衰减速度**（前 3 天最陡）：

| 天 | R 值 |
|:--:|:--:|
| 第 1 天 | 60%~70% |
| 第 2 天 | 40%~50% |
| 第 7 天 | 20%~30% |
| 第 30 天 | 10%~15% |

**多级间隔的数学逻辑**：每次成功检索 → S 增大 → 衰减变慢。四次检索后（L1~L4），54 天后的 R 仍 > 0——等效于单一最优间隔，但没有全忘风险。

```
[EXECUTE] → S=S₀ → [L1 当天] → S=S₁ → [L2 半天] → S=S₂ → [L3 2天] → S=S₃ → [L4 7天] → S=S₄
```

### 最优间隔公式

```
最优间隔 ≈ 保留时长 × 10% ~ 20%
```

| 保留时长 | 10% 法则 | 场景 |
|---------|---------|------|
| 1 个月 | 3 天 | 月考 |
| 6 个月 | 18 天 | 期末 |
| 18 个月（考研） | 54 天 | 理想，不现实 |

> 54 天单次间隔 → 前面全忘光 → 等于从头学。所以不用单一间隔，用四级。

### 四级间隔架构

| 级别 | 做什么 | 间隔 | 记忆阶段 | 流水线 |
|:--:|------|:--:|------|:--:|
| L1 | 章节练习 | 当天 | 编码 | EXECUTE |
| L2 | 傍晚抽检 2 道 | 半天 | 探 L1 evict 率 | WRITEBACK |
| L3 | 章总练习题 | 2 天 | 巩固（睡眠后） | WRITEBACK |
| L4 | 周末跨章抽检 | 7 天 | 检索 (interleaving) | WRITEBACK |

### 为什么 L3 = 2 天（Bjork desirable difficulty）

- 当天：L1 cache 热着，对了是假象
- 7 天：忘太多，触发逃避
- **2 天**：遗忘刚开始但没全忘 + 睡眠 consolidation 已完成 → 检索吃力但可成功 → 加固最显著

### 三科适配

| 科目 | 间隔策略 | 特殊处理 |
|------|---------|------|
| 数学 | L1~L4 全线 | 总练隔 2 天；傍晚抽检每天 |
| OSTEP | L1 不适用（异步） | 消化延迟几天后做作业；旧债日补 1 章 |
| 英语 | L1 当天，L4 周末 | 语法习题当天；造句融入 daily routine |

## PDP 1.1 — 数学诊断系统

### 新章诊断

```
关书 → 抽 5 道基础题 → 独立写出几道？
  ├── 5 道全对 → 🟢 跳过
  ├── 2~4 道  → 🟡 补漏专项练习
  └── 0~1 道  → 🔴 重学整章
```

### 做题梯度

```
独立尝试 → 卡住 → 看题解 → 关书复现全过程+标每步原因 → 写触发信号+标遗漏
   ↑                                                           ↑
  独立解出 (Y)                                                  复现 (X)
```

### 复现失败的自诊

| 症状 | 卡在哪 | 修复 |
|------|------|------|
| 题解完全看不懂 | FETCH（前置缺口） | 圈出那一行→定位知识点→单点突破 |
| 看懂但合书写不出 | DECODE 假阳性 | 分段复现：看一段→合上写一段 |
| 能复现但新题不会 | WRITEBACK（缺触发信号） | 找共同模式→写成一行触发规则 |
| 做对了说不清 | DECODE 表面 | 每步自问「不用这步会怎样？」 |

### 连续提示依赖：共享缺口修复 [PAUSED]

**触发条件**：连续 2 道以上题目都必须逐步问 AI/看答案，才能复现完整过程。

> 这不是“再多刷几题”。它可能表示多道题共用一个未加载的前置依赖；先验证共同卡点，避免每题重复补同一处漏洞。

```text
1. 停止当前题组；每题只记录「第一次卡住的步骤」。
2. 找出现 ≥2 次的同一知识点/变形/触发信号。
3. 回教材只补这个共同点 15 分钟；不扩展到整章。
4. 关书复现 1 道最基础例题。
5. 做 2 道同类基础题，记录“不问 AI 能否写出第一步”。
```

|  2 题检验结果  | 诊断           | 下一步                   |
| :-------: | ------------ | --------------------- |
| 2/2 或 1/2 | 共同缺口假设暂时成立   | 继续按共享依赖修复，不逐题硬抗       |
|    0/2    | 共同点找错，或缺口更底层 | 退回一步，重新定位更基础的定义/公式    |
| 连续两轮 0/2  | 当前材料或题目层级不匹配 | 降到更基础题或重学该节；不增加 AI 提示 |

**验收指标**：不是题数，而是后续同类题中“无需 AI 也能写出第一步”的比例是否上升。

# PML4 2：运行时调度

## PDP 2.0 — Throughput 追踪

> 详见 `Throughput.md`

### 指标（v3.0）

| 科目 | 记录方式 | 时间口径 |
|------|---------|---------|
| 数学 | 固定记录：复现 X / 独立 Y；主题写入产出文本 | 当天数学 block 的总专注时长 |
| OSTEP | 自由记录可复查的关书解释、流程图或作业；不统计条数 | 仅今天产出实际耗时，阅读不记 |
| 英语 | 自由记录造句、习题、默写等可检查产出 | 当天英语 block 的总专注时长 |
| 其他 | 必须写具体任务与产出；规划、改模型、娱乐不计入 | 实际学习时长 |

### 每日最小完成单元（跨文件接口）

> **内容边界的唯一来源**：`Myplans.md`。数学模块、OSTEP 章节和英语最末级知识点如何拆分，只在该文件定义。
>
> **产出验收的唯一来源**：`Throughput.md`。数学复现/独立、OSTEP 关书输出、英语可检查产出的口径，只在该文件定义。
>
> 总模型只规定二者的关系，不复制具体清单，避免三个文件各自演化后产生版本漂移。

```text
Myplans：今天推进到哪里（调度边界）
Throughput：今天实际留下什么（运行数据）
总策略模型：为什么这样调度、何时允许修改（架构）
```

### 任务隔离准则

```text
一个任务卡住、做错或状态差 ≠ 其他任务取消。
数学失败，OSTEP照常开始；OSTEP慢，英语最小完成单元照常启动。
不允许把前一任务的失败结算给后一任务；当天产出按 Throughput 的真实数据记录。
```

### 节奏

```text
每日执行 → Throughput 留痕 → 周复盘 → 用户决策 → 新参数运行
```

### 反作弊自审

1. 数学复现：每步原因自己写的还是抄书？
2. OSTEP 关书输出：机制、条件与因果是自己写的，还是变相抄书？
3. 英语造句：先自己造再查语法，还是翻译完抄？

## PDP 2.2 — 中断处理

| 中断 | 触发 | ISR |
|------|------|-----|
| 幻想.exe | 疲劳时播放「成功画面」 | 「幻。」→ 读题干第一句 → 写一个字 |
| 焦虑中断 | 「能不能考上？」 | 回到当前时间片的下一分钟 |
| 手机打断 | 触手可及时 | 学习开始前静音→放书包最内层→书包离座位 ≥ 2 米；三科最小完成单元提交前不取出 |
| 贪多中断 | 新资源/新方向 | 写进 backlog，不改当前时间片 |

### 手机与克制偏差（restraint bias）

> 克制偏差：人在诱惑尚未出现、状态冷静时，会系统性高估自己在疲劳或挫败状态下抵抗诱惑的能力。

**运行证据**：

```text
07.26：回家刷手机 → 英语只剩约7分钟
07.28：白天看手机 → 任务整体后移到晚上
07.30：大部分时间花在手机上 → 三科最小完成单元全部未完成
08.04：打开书前长时间刷手机 → 启动延迟、注意力反复切换 → 焦虑累计时长 → 更难进入任务
```

因此，“我觉得自己能控制住”已被连续运行数据证伪。在当前已记录的多次执行故障中，手机是出现最频繁、损失范围最广的共同上游节点；手机是否留在身边不再交给临场自控决定。

### 手机启动抢占反馈环

```text
初始不适 / 启动摩擦
        ↓
第一个任务开始前刷手机
        ↓
注意力残留 + 工作集未加载，学习启动延迟
        ↓
当天有效学习时间减少
        ↓
反复计算“今天还差多少小时”
        ↓
焦虑占用工作记忆，当前任务主观阻力继续上升
        ↓
更难进入任务，并再次倾向用手机退出
```

这不是“状态差”和“刷手机”之间的二选一因果。初始疲劳或抗拒可能提高拿手机的概率，但手机会进一步放大启动失败；实时盯住累计时长又构成第二级放大器。控制策略不追问谁是唯一第一因，而是优先切断最可控、已反复出现的增益节点。

```text
第一个学习任务开始前：手机静音 → 书包最内层 → 书包离座位 ≥ 2 米
三科最小完成单元提交前：不取出；查资料使用电脑
```

这不是惩罚，而是权限隔离：撤销一个已连续失效组件的运行时访问权限。

**优先级**：EXECUTE 中的进程 > 任何中断（除非身体需求）

## PDP 2.3 — 反馈循环

```
日追踪 → 周复盘(反作弊+校准) → 模型迭代 → 新一周新参数
   ↑                                      ↓
   └──────────── 按新参数运行 ──────────────┘
```

**每周日自问**：哪个指标要调？目标松还是紧？新中断源？

### 模型变更权限（write buffer）

```text
执行期（当天任务未完成）：
  模型文件 = 只读。
  新问题只写入当天 Throughput 备注：触发 → 行为 → 损失。
  不创建不存在的 Inbox，不在运行期修改总模型正文。

周复盘期：
  读取本周 Throughput + 当前实验寄存器。
  只有同时满足：① 重复或高损失证据 ② 可观察指标 ③ 可执行干预 ④ 回滚条件，
  才允许把问题晋升为实验规则。
```

这不是压制念头，而是 write buffer：每日故障先进入数据层，周复盘才有权限进入架构层。

## PDP 2.4 — 防 Bug 系统

> 中断处理系统（PDP 2.2）管的是**运行时打断**。这里管的是**已知会反复出现的结构性故障**——不是意外，是可预测的崩溃模式。
>
> **Bug 来源**：每一个条目必须是你亲自观测到的、反复发生的崩溃模式。不替身，不预判。

### Bug 寄存器

| Bug ID | 触发条件 | 崩溃行为 | 损失 | 根因 |
|:--:|------|------|:--:|------|
| **B1** | 坐下后觉得「模型还不够好」 | 打开 Obsidian 调模型→1h 后数学书还没翻开 | ~6 道题 | B 在调度启动前劫持：假建造替代真建造 |
| **B2** | 第一个学习任务开始前手机仍可访问 | 打开书前长时间刷手机→启动延迟→开始焦虑累计时长→更难进入任务 | 任务整体后移、英语被压缩，严重时三科未完成 | 手机在启动窗口抢占调度；即时退出被负强化，时长焦虑继续放大阻力 |

### 防御机制

**B1 · 完美主义 → 假建造**

```
这是 B 最狡猾的战术：让你做一个「感觉像建造」但不是建造的事。
调模型格式、加链接、改版本号——全是 NOP 指令，CPU 看起来在工作，throughput=0。

防御（最小启动）：
  触发条件 = 坐下
  动作 = 翻开数学书，写一道题。任何题。昨天做过的也行。
  写完之前，Obsidian 不打开、模型不改、链接不加。
  写完一道 → 你自由了。改模型、调格式，随便。
       但 90% 的情况是：写完一道之后你已经不想改模型了——你在数学里了。

为什么有效：B 的攻击窗口是「坐下后、打开数学书之前」的 ~2 分钟。
       最小启动把这个窗口压缩到零。你还没意识到「模型不够好」，
       手已经在写题了。B 没机会发射。
```

**B2 · 手机启动抢占 → 时长焦虑反馈环**

```text
预防：
  进入图书馆之前：手机静音 → 书包最内层。
  到座位后：第一个拿出的物体只能是当天第一本书。
  三科最小单元提交前：不取手机；学习过程中不计算当天累计时长。

如果已经在启动前刷手机：
  立即收起手机 → 不计算已经损失多久 → 打开当前任务 → 只写第一个可验证动作。
  当天结束后再统一回填实际耗时，不在运行时给当天判刑。
```

**验收**：不是“今天有没有玩手机”的道德判断，而是手机是否在第一个学习动作之前获得前台权限；若未获得，则启动防线生效。

### 系统调用约定

以上所有防御都是**预编译的决策**。触发条件满足 → 自动执行，不重新谈判。B 的战术就是在你犹豫时插入决策点——预编译消除了决策点。

## PDP 2.5 — 目标函数与时间预算

### 目标函数：能力，而不是时钟

三科对应三种仍然愿意主动建造的能力：

| 管道 | 服务的目标 |
|------|-----------|
| 数学 | 考研基础 + 形式化推理能力 |
| OSTEP | 对计算机底层机制的深入理解 |
| 英语 | 考试能力 + 直接读取英文资料的权限 |

学习时间只是为这些目标分配的**容量预算**，不是目标函数本身。`6h` 与 `7.75h` 都只能表示预估可用容量；它们不自动等于能力增长，也不承担“证明我足够努力”或“证明我不是废物”的功能。

```text
错误链：能力增长 → 给时长指标交差 → 为凑够时间而空转
正确链：能力目标 → 三科可验证提交 → 时间作为成本被记录
```

### 时间指标的权限边界

> **每日主验收**：三条管道是否完成当天最小单元，并留下各自的 EXECUTE 产物。
>
> **时间的权限**：用于容量规划、周复盘和发现异常；不得单独充当当天成败判决。

如果三科已经提交，5h08min 不因为低于 6h 而失败；为了补满剩余时间继续坐着，可能只是 busy waiting。反过来，学习 6h 但没有可检查产出，也不能通过验收。

日程中的计划时长仍可保留，它是资源预算而不是强制最低运行时间。三科全部提交之后，可以自愿加餐；没有明确任务时，不为凑数延长运行。

### “逼自己”的合法调用范围

```text
允许：已经选择任务但迟迟未启动 → 用最小动作跨过启动摩擦。
      例：打开书 → 写第一题第一步 → 进入当前时间片。

禁止：任务队列已经提交，只因时钟未达到目标 → 强迫继续空转。
```

强制只负责唤醒进程，不负责制造虚假 CPU 利用率。热情不是调度器；启动可以预编译，但运行时长必须服务于明确任务。

### 调度公平：三科提交前禁止单科加餐

```text
数学最小单元提交 → 抢占
OSTEP 最小单元提交 → 抢占
英语最小单元提交 → 三条管道全部 commit
全部提交后 → 才允许任意科目加餐
```

最小单元是调度提交边界，不是“这一科必须做到爽为止”。局部受阻只降低该进程的吞吐，不得把故障传播给后续科目。

### 三天诊断：6h 是真实成本还是虚假配额

连续三天运行同一协议，不永久修改日程：

1. 保持数学 → OSTEP → 英语的原顺序。
2. 每科提交最小完成单元和可检查产出。
3. 继续如实记录实际专注时间，但不以“是否满 6h”判定成败。
4. 三科提交后，仍有明确任务且自愿继续才加餐；否则结束。
5. 三天后按结果分类：
   - 三科完成，时间自然接近 6h：6h 是真实工作量的结果。
   - 三科完成，只需 4–5h：6h 是虚假配额，不应强行补齐。
   - 三科经常无法完成：检查任务粒度、调度或中断，不先归因于“不够狠”。

### 运行证据（08.03）

- 当天 5h08min，数学、OSTEP、英语均有可检查产出；低于 6h 不等于执行失败。
- 在取消计时、记录和外部评价的假设下，仍愿意主动学习三科，说明当前证据不支持“学习欲望已经消失”。
- 当前冲突发生在“我愿意学习”与“我必须凑够 6h”之间，因此先校准时间指标，不把它误诊为目标彻底失效。

## PDP 2.6 — 可持续迭代内核

### 0. 目标与验收

可持续迭代不是“模型可以一直加东西”，而是每条规则都能回答：

```text
为什么进入？→ 现在处于什么状态？→ 用什么数据判断？
→ 谁给建议、谁做决定？→ 无效时怎样退出？
```

第三方验收标准：任取一条非稳定规则，都能在本页找到它的状态、证据、干预、复盘时间和退出条件；找不到则不得部署。

### 1. 规则生命周期

```text
[OBSERVED 观察]
      ↓ 周复盘立项
[EXPERIMENTAL 实验]
      ├── 证据不足 → CONTINUE 继续实验
      ├── 干预需改 → REVISE 修改后重新运行
      ├── 有效且可承受 → STABLE 晋升稳定规则
      ├── 无效/副作用过大 → ROLLBACK 回滚
      └── 已被替代/不再适用 → DEPRECATED 废弃
```

| 状态 | 含义 | 文件权限 |
|------|------|---------|
| `OBSERVED` | Throughput 中出现的故障事实，尚未形成解决方案 | 只写数据，不改模型规则 |
| `EXPERIMENTAL` | 已声明指标、期限和回滚条件，正在运行 | 规则必须显式标注实验态 |
| `CONTINUE` | 到复盘点但证据不足，原规则继续运行 | 必须给出新复盘日期 |
| `REVISE` | 假设保留，但干预动作发生变化 | 生成新版本并重置观察窗口 |
| `STABLE` | 数据支持有效，用户愿意继续，正式进入对应 PDP | 正文默认均为稳定规则 |
| `ROLLBACK` | 无效、损失扩大或副作用不可接受 | 撤销干预，恢复上个稳定版本 |
| `DEPRECATED` | 环境变化或被新规则替代 | 从正文删除，只在版本日志留一行 |

### 2. 实验卡：进入内核的最小 ABI

每条 `EXPERIMENTAL` 规则必须具备以下字段，缺一项不得部署：

| 字段 | 必须回答的问题 |
|------|---------------|
| 实验 ID | 如何唯一引用这次实验？ |
| 问题证据 | Throughput 中哪几天出现了什么损失？ |
| 假设 | 哪个可干预节点造成或放大了损失？ |
| 干预动作 | 触发后具体执行什么？ |
| 观察信号 | 外部观察者能记录什么变化？ |
| 运行窗口 | 从哪天开始，哪天复盘？ |
| 回滚条件 | 出现什么结果立即停止或恢复旧规则？ |
| 主观负担 | 用户是否愿意让它原样再运行一周？负担是什么？ |
| Agent 判断 | 数据支持、证据不足还是反驳？副作用与冲突是什么？ |
| 用户决策 | `STABLE / CONTINUE / REVISE / ROLLBACK / DEPRECATED` |

### 3. 人机协同治理

```text
用户：提供真实体验、指出运行负担、保留最终 root 权限。
Agent：读取 Throughput，检查因果顺序、指标完整性、副作用和跨文件矛盾，给出建议。
最终决定：由用户做出；Agent 不以权威替用户决定，用户也不必用感觉伪装成客观证据。
```

周复盘时分开回答两类问题：

1. **有效性**：数据是否支持规则降低了目标损失？由 Agent 基于记录给出判断。
2. **可持续性**：用户是否愿意让规则原样再运行一周？由用户基于真实负担回答。

二者冲突时，不自动晋升：有效但负担过重 → `REVISE`；体验良好但证据不足 → `CONTINUE`。

### 4. 自适应 WIP 与准入控制

不设固定实验数量上限。用户感到累时可以主动减少，但任何实验不得无声烂尾。

新增实验前必须执行：

```text
列出当前所有 EXPERIMENTAL / CONTINUE 项
→ 用户判断是否愿意把“现有项 + 新项”一起运行到下次周复盘
→ 愿意：准入
→ 不愿意：先对至少一项做出 PAUSE / ROLLBACK / DEPRECATED 决策，再准入
```

“累了”拥有降载权限，但降载必须落成一个明确的状态变更，不能只停止记录。

### 5. 周复盘事务

```text
① 读取：本周 Throughput + 实验寄存器
② 对账：实验要求的数据是否真的留下
③ 用户报告：愿不愿意原样再跑一周；具体负担是什么
④ Agent 判断：支持 / 证据不足 / 反驳；列出副作用和文件冲突
⑤ 用户提交最终决策
⑥ 原子更新：规则正文 + 实验寄存器 + 版本日志
```

未完成第 ⑤ 步，不允许执行第 ⑥ 步。一次复盘只提交已经明确决策的变更，不顺手改无关章节。

### 6. 三文件单一事实来源（Single Source of Truth）

| 文件 | 唯一负责 | 禁止复制 |
|------|---------|---------|
| `Myplans.md` | 日程、内容范围、最小完成单元和拆分边界 | 不复制理论与执行数据 |
| `Throughput.md` | 每日耗时、可检查产出、故障事实 | 不复制完整理论和长期规则 |
| `总策略模型.md` | 架构、稳定规则、实验生命周期和理论解释 | 不复制每日内容清单 |

一条实验若改变跨文件接口，实验卡必须列出受影响文件；只有用户明确提交最终决策后，才在同一事务中更新这些文件。禁止未经授权“顺手同步”。

### 7. 回滚、废弃与文档收敛

- `ROLLBACK`：撤销实验干预，恢复上一个稳定行为；版本日志记录原因。
- `DEPRECATED`：从正文删除旧规则，不保留长篇尸体；版本日志仅留“被什么替代、为何退出”。
- `STABLE`：把规则合并到负责该问题的 PDP，实验卡从活动区移除。
- 每次周复盘只允许模型净增长来自已晋升规则；被替代内容必须同时删除，禁止无限 append-only。
- 版本号记录行为语义变化，不为排版、错字或链接修复升级主版本。

## PDP 3.0 — 底层理论支撑

### 手机启动故障：理论链

> 这组理论不是为了给“刷手机”贴道德标签，也不证明手机是所有低吞吐日的唯一原因。它们解释的是：为什么手机一旦在第一个学习动作之前获得前台权限，就可能把普通启动摩擦放大成持续停机；最终因果强度仍由后续运行数据验证。

#### T1 · 克制偏差（restraint bias）：为什么不能把手机留在手边

克制偏差指人在诱惑尚未真正出现、状态相对冷静时，会高估自己之后抵抗诱惑的能力。计划阶段的“我只看一下”“我随时能停”不是可靠预测，因为真正决策发生在疲劳、抗拒或即时奖励已经出现之后。

```text
冷静状态下高估自控力
→ 允许手机保持可访问
→ 启动摩擦出现时临场谈判
→ 高即时奖励的手机进程获得前台权限
```

**模型推论**：防线必须部署在诱惑出现之前。手机是否可访问属于环境权限配置，不交给运行时意志力。

#### T2 · 负强化（negative reinforcement）：为什么“状态差就刷手机”会被训练得越来越稳定

负强化不是惩罚，而是一个行为因为暂时移除了不适刺激，所以未来更容易重复。开始学习时的无聊、困难、焦虑属于厌恶刺激；拿起手机后，这些不适暂时消失，大脑便学到“启动不舒服 → 退出到手机”的策略。

```text
启动任务产生不适
→ 刷手机后不适暂时下降
→ “刷手机”这一退出行为被强化
→ 下次出现更小的启动摩擦也更容易触发同一行为
```

**模型推论**：不能靠自责消除已经被强化的行为链。必须取消手机这个低成本退出通道，并用“只写第一步”替换退出反应。

#### T3 · 注意力残留（attention residue）：为什么放下手机后仍然难以静下心

从一个任务切换到另一个任务时，注意力不会瞬间全部迁移；前一个任务的目标、刺激和未完成信息会残留，占用一部分认知资源。手机的信息流由大量快速切换的小目标构成，放下手机只是结束输入，不代表数学或 OSTEP 的工作集已经完成加载。

```text
手机高频切换
→ 前一批刺激仍占用注意资源
→ 学习任务的工作集加载不完整
→ 重读、走神、启动延迟
→ 当前任务被主观判断为“特别难进入”
```

**模型推论**：“脑雾”只作为主观描述，不当作医学诊断；真正记录的是打开书的延迟、重读、切换冲动和第一个产出的完成时间。预防优于刷完后的恢复。

#### T4 · 注意控制理论（attentional control theory）：为什么时长焦虑会继续降低执行效率

焦虑不一定让能力消失，但会降低认知加工效率：注意资源更容易被威胁信号和刺激驱动系统捕获，目标导向控制变弱。对刷手机后损失时间的反复计算，会把“今天还差多少小时”变成持续运行的威胁线程，与当前题目竞争工作记忆。

```text
发现学习时间减少
→ 反复计算距离目标时长还有多少
→ 威胁监控占用工作记忆
→ 当前任务可用注意资源下降
→ 任务更慢 → 时间焦虑进一步上升
```

**模型推论**：运行期间禁止累计和判决当天总时长；只处理当前单元，结束后再统一回填时间。

#### T5 · Goodhart 定律：为什么越盯学习时长，反而越学不好

Goodhart 定律：当一个测量指标变成目标，它就不再是可靠指标。学习时长原本只用于估算投入成本；一旦被用来判定“今天是否成功”，行为就会开始围绕时钟优化，而不是围绕能力产出优化。

```text
时长 = 观测指标
→ 时长被升级为每日目标
→ 注意力转向凑够数字、避免失败判决
→ 产出质量与时间数字脱钩
```

**模型推论**：每日验收看三科是否留下可检查的 EXECUTE 产物；时长只在一天结束后用于容量分析，不在执行中参与调度。

#### T6 · 控制论正反馈：为什么不必先争论“状态差导致玩手机，还是玩手机导致状态差”

两个方向可以同时存在，形成正反馈环。初始疲劳、焦虑或抗拒可能提高拿手机的概率；手机又通过注意力残留和启动延迟降低学习吞吐；损失时间随后触发时长焦虑，再进一步提高退出冲动。

```text
初始不适
→ 刷手机
→ 启动延迟、吞吐下降
→ 时长焦虑
→ 目标导向控制变弱
→ 更难启动 / 更想刷手机
        ↺
```

控制闭环不要求先找到唯一第一因。工程上优先切断**可控制、重复出现、增益最大的节点**：学习前手机访问权限和运行中的累计时长检查。

| 故障节点 | 理论解释 | 已观察信号 | 对应干预 |
|---------|---------|-----------|---------|
| 手机留在手边 | 克制偏差 | 多次相信能控制，最终长时间刷手机 | 进入图书馆前物理隔离 |
| 启动不适后拿手机 | 负强化 | 手机成为低成本退出通道 | “只写第一步”替代退出 |
| 放下后仍难集中 | 注意力残留 | 重读、切换冲动、启动延迟 | 手机不得在首个任务前获得权限 |
| 焦虑今天学得太少 | 注意控制理论 | 反复计算剩余时长，任务继续变慢 | 结束后再统计总时长 |
| 为达到 6h 而运行 | Goodhart 定律 | 时长开始替代产出成为成败标准 | EXECUTE 产物作为主验收 |
| 状态与手机互相放大 | 控制论正反馈 | 启动摩擦→手机→焦虑→更难启动 | 同时切断手机访问与实时计时 |
